# 结果页重组:按链路分组 + 问题挂到流 + 点对点链路

## 目标效果

- 页面重组为「音频」「视频」两个大区块,替代原「声音问题分类 / 视频问题分类」独立大区块
- 每个区块内按**链路方向分组**:`主叫 → FS → 被叫` 一组、`被叫 → FS → 主叫` 一组;**点对点时去掉 FS** 变成 `主叫 → 被叫`
- 每组下**流卡片两列并排**,问题直接挂在对应流卡片下:严重(critical)展开标红,注意/提示级收进折叠区可点击展开
- 归属到方向(而非单条流)的问题挂在链路头上;无法归属的(fs_relay、fs_delay 等全局问题)挂在区块尾部

## 后端改动(2 个文件)

### analyzer/problem_taxonomy.py
1. `_Collector.add()` 增加 `streams=None, directions=None` 可选参数,按问题 id 累积去重;`output()` 在每个问题条目上新增 `streams: [...]`、`directions: [...]` 两个列表字段
2. `classify_problems()` 各调用点补传归属:
   - 流级检测(packet_loss、rtcp、audio_quality、ts_continuity、jitter)→ `streams=[label]`
   - 方向级检测(audio_health.directions、delay_chains.directions、roundtrip)→ `directions=[label 或 pair]`
   - 全局检测(fs_relay、fs_delay)→ 不传(留在区块级)

### analyzer/video_problem_taxonomy.py
同样处理:video_quality/packet_loss/rtcp/ts_continuity/jitter → streams;视频延迟方向 → directions;fs_relay → 不传。

## 前端改动(templates/results.html + static/css/style.css)

1. **链路助手 `_chainHtml()`**:统一渲染 `主叫 → FS → 被叫`;p2p 判定取 `report.audio_health.p2p || report.delay_chains.p2p`,点对点时输出 `主叫 → 被叫`。应用到:
   - 新的音/视频区块每个方向组的组头
   - 无声诊断 `renderAudioHealth`、分段延迟 `renderDelayChains` 的方向头(替换纯文字 label)
   - 音视频回放 `_partyChainHtml`:p2p 时不再渲染 FS 段
2. **新函数 `renderMediaSections(report)`** 替代 `renderProblemClassification` / `renderVideoProblemClassification` / `_qualityOverview`:
   - 从流 label(形如 `seat (SSRC=0x12345678)`)解析角色与 SSRC,建立 SSRC→流 的映射
   - 方向→流映射:用 audio_health 该方向 legs 的 SSRC + delay_chains 同名方向 segments 的 SSRC(含 `0xA → 0xB` 形式)匹配流;视频无 audio_health,按角色前缀分组回退,FS 中转流按 SSRC 归组、匹配不上则归"FS 转发"组
   - 每组:链路头(组 verdict 徽章 + 方向级问题) + 流卡片两列网格(`col-md-6`)
   - 流卡片:角色徽章 + 流名 + 质量 verdict 徽章 + 现有指标 chips(`_audioQualityChips`/`_videoQualityChips` 复用) + 该流问题(critical 用 `_problemCard` 展开,其余收进 `<details>`)
   - 区块尾部:全局问题 + `unobservable` 折叠表(保留现有形式) + summary
   - 旧会话数据无 streams/directions 字段时,回退用 evidence 文本前缀对流 label 做匹配
3. **style.css**:新增方向组、流卡片网格、链路头样式(复用现有 badge/border 风格)
