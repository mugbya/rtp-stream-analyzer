# 流识别结果规则

本文整理网页第 2 步「流识别结果」展示内容背后的判定规则,对应代码:

- `src/analyzer/rtp_parser.py` — RTP/RTCP/SIP 解析、流种类(kind)判定
- `src/analyzer/stream_classifier.py` — 音视频分类、服务器 IP 识别
- `src/analyzer/call_detector.py` — 通话分组、信令关联、抓包完整性
- `src/app.py` — 识别入口(`detect` 接口)

「流识别结果」包含四块内容:服务器 IP、音频/视频流统计、各抓包文件明细表、通话列表(含完整性与一致性提示)。

---

## 一、RTP 流提取

1. 抓包中所有 UDP 包先做 IP 分片重组(带 SDP 的大 SIP 消息超过 MTU 时只有首片带 UDP 头,不重组会解析不到 SDP)。
2. 按 SSRC 聚合成流,记录:包数、出现过的 PT 集合、端点 IP 集、(src ip, src port, dst ip, dst port) 组合列表、首末包时间。
3. **包数 < 10 的流直接丢弃**(噪声/零星杂包不构成流)。
4. RTP(端口不限、按头解析)与 RTCP(SR/RR)分开;类型 200/201 的 RTP 包按 RTCP 处理。
5. 展示层过滤组播与非法 IP(224./239.、0.0.0.0、255.255.255.255)。

## 二、音视频流分类

动态 PT(96–127)按媒体种类独立分配,同一号码在 audio 与 video 两个 m= 行里可以指不同编码(实测:audio 96=OPUS、video 96=H264 同号并存),**只看 PT 号会把 OPUS 音频误判成视频**。因此按四级证据链判定,前者有结论即停:

| 级别 | 证据 | 规则 |
|---|---|---|
| 1 | SDP 端口绑定(权威) | 流两端 (ip, port) 命中 SDP `c=`/`m=` 行宣告的媒体端点,只命中 audio → 音频,只命中 video → 视频 |
| 2 | rtpmap 单侧命中 | 流的主 PT(所有 PT 中编号最小者)只出现在某一类媒体的 rtpmap 里 → 定种类;两端同号复用时不作数 |
| 3 | 实测 RTP 时钟率 | 无信令抓包里唯一可靠的信号。时钟率 = Σ(时间戳增量)/Σ(到达间隔) 的中位数(相邻样本间隔 >1ms、时间戳增量为正才计入,样本 <4 个不判);落入 81000–99000 → 视频,落入 7200–8800 或 43000–53000 → 音频(对应 8k/48k 音频时钟) |
| 4 | 静态 PT 表兜底 | 无任何上述证据时维持旧口径:PT ∈ {0, 3, 8, 9, 18} → 音频(PCMU/GSM/PCMA/G722/G729);PT ∈ 96–127 → 视频 |

四级都判不出 → `unknown`。

分类入口 `classify_all_streams`:流信息带解析阶段标注的 `kind` 时直接采用;没有时才回退到按 PT 号判断(仅第 4 级逻辑)。

**编码与钟率解析**:codec 名优先取 SDP rtpmap,静态 PT 用内置表;时钟率 audio=8000(G722 采样 16k 但按 RFC 3551 RTP 时钟仍是 8000)、video=90000,OPUS 特例 48000。

## 三、服务器 IP 识别

服务器(通常是 FS)转发所有流,在 RTP 端口对里出现次数必然最多:

1. 统计每个 IP 在全部流 `port_pairs` 两端的出现次数;
2. 出现次数**唯一最大**的 IP → 服务器;
3. **打平**(单侧抓包的典型形态,各端点次数必然相同)时用 SIP INVITE 的 Via 头数消歧:
   - 只有 1 条 Via:INVITE 是主叫终端自发 → 服务器取 INVITE 的**目标** IP;
   - 有 ≥2 条 Via:INVITE 经 FS 转发而来(抓包点在被叫侧)→ 服务器取 INVITE 的**来源** IP;
   - 候选 IP 必须在流量统计里出现过才采用;
4. 消歧失败 → 退回次数第一名;完全无流量 → 未检测到,页面显示「单端分析模式」。

## 四、通话识别

通话由「腿」(conversation / leg)聚成,分四步:

### 1. 单文件内建腿

- 同一对端点 `(ip, port) ↔ (ip, port)`(双向合并)的 RTP 包聚成一条腿;
- 同端口对上**不活跃间隔 > 30s 即切段**(后一通电话复用端口;RTP 按 20ms 发包,活跃通话不会出现 30s 无包)。

### 2. 跨文件合并

同一媒体流的 SSRC 在每个经过的抓包点都相同,**共享 SSRC 的腿合并**为一条(跨抓包去重),并按角色记录各文件的媒体时间与首序号。

### 3. 聚成通话(初分)

- 共享 SSRC → 直接并;
- 否则需满足:**时间重叠 > 0.7 × min(双方时长)** 且**至少共享一个 IP**(对向腿共享服务器 IP,同侧音视频腿共享端点 IP);
- 并发/交错经同一服务器的通话会被误并成一通,由下一步拆回。

### 4. 按信令对话框全局重绑(refine)

先从 SIP 事件构建对话框视图(按 Call-ID):SDP 宣告端点集、信令时间范围、非服务器信令对端 IP。然后把**全部**媒体腿与**全部**对话框一次性重绑(逐通话拆分会把缺头/缺尾通话的残腿错并进时间重叠的其他通话):

1. **强绑定**:腿的端点 (ip, port) 命中对话框 SDP 宣告、且媒体时间与对话框相交(时间窗两端放宽 6s:BYE 前媒体先停、INVITE 后媒体才起都算相交;抓包前已建立、只剩 re-INVITE/BYE 的通话靠放宽命中);
2. **对端绑定**(无 SDP 宣告的对话框):腿的非服务器 IP 命中对话框信令对端、媒体时间相交;多候选取媒体结束/开始贴对话框末条/首条消息最近且 ≤6s 的;腿×对话框唯一组合则直接绑定不问远近;
3. **半呼叫形状合并**:共享对话框的腿先聚成组件,组件两两满足「媒体时间重叠 > 0 + 合并后非服务器端点 ≤ 2 + 媒体结束时间相差 ≤ 3s」才并成通话——B2BUA 一通电话两侧腿并发、挂断时同时停流;冒出第 3 个端点或挂断时刻对不上即另一通电话;
4. **游离腿**:非服务器 IP 命中某通话组件且时间重叠的归入;否则按第 3 步旧规则(时间重叠 + 共享 IP)自聚成无信令通话(典型是缺信令的第二通电话),同样可选为分析目标。

**SIP 信令关联**:信令按 Call-ID 分组去重后,归属到媒体时间窗(±15s)覆盖其首条消息、且 SDP 宣告端点命中最多 → 信令对端 IP 命中最多 → 重叠最大的那一通;去重口径为 30s 窗口内同 Call-ID + method + CSeq + src + dst,多抓包副本按角色优先级 fs > terminal > seat 保留单一时钟来源的那份。

## 五、通话抓包完整性

按通话自己的信令(有 Call-ID 匹配时只认本通话的 INVITE/BYE)与媒体序号逐文件评估:

**开头是否抓到**(满足其一即完整):

1. 媒体开始前 1s 内有本通话 INVITE → 已抓到;
2. 上行流(源 ≠ 服务器)首包 seq ≤ 50,且该流在通话媒体开始后 3s 内已出现 → 媒体从头被捕获;首包 seq 明显非零 → 缺开头;通话开始距抓包开始 < 3s 且无其他证据 → 缺开头。

**结尾是否抓到**:

1. 媒体结束后 1s 内有本通话 BYE → 已抓到;
2. 否则媒体结束距抓包结束 < 3s → 缺结尾(抓包结束时通话可能仍在进行);≥ 3s → 自然结束。

总体状态取各文件中**最差**者:`完整` / `缺开头` / `缺结尾` / `首尾都不完整`。

## 六、点对点直连与「传错文件」检测

- **点对点直连**:通话所有腿的端点都不含服务器 IP → 媒体两端直连(bypass media),服务器抓包里天然没有这通电话;
- **跨抓包一致性**:正常情况下多份抓包至少共享一通通话(共享 SSRC 会合并);若某两个角色之间找不到任何共同通话 → 提示可能传错文件;
- 例外:「无共同通话」的角色对都含服务器侧抓包、且其余角色之间确实共享一通点对点直连通话(两端都抓到)→ 不提示传错,改为提示点对点直连,可直接选该通话分析(不使用服务器数据)。

## 七、阈值速查

| 常量 | 值 | 用途 |
|---|---|---|
| 最小流包数 | 10 | 低于此数的流丢弃 |
| 音频静态 PT | 0, 3, 8, 9, 18 | PCMU/GSM/PCMA/G722/G729 |
| 动态 PT 范围 | 96–127 | 默认按视频(兜底) |
| 实测时钟·音频 | 7200–8800 或 43000–53000 | 对应 8k / 48k |
| 实测时钟·视频 | 81000–99000 | 对应 90k |
| 时钟估计最小样本 | 4 个间隔 | 不足不判 |
| 端口复用切腿间隔 | 30 s | 同端口对不活跃超时切段 |
| 通话聚类重叠比 | 0.7 | 重叠 > 0.7×min(时长) 且共享 IP |
| 对话框绑定放宽 | 6 s | 媒体与对话框时间相交的放宽量 |
| 半呼叫结束对齐 | 3 s | 两单元媒体结束时刻差上限 |
| 半呼叫端点上限 | 2 个非服务器端点 | 超出即另一通电话 |
| 信令关联窗口 | 15 s | Call-ID 组首条消息距媒体窗 |
| 信令去重窗口 | 30 s | 同 Call-ID+method+CSeq+src+dst |
| 缺开头边界 | 3 s(时间) / seq ≤ 50(序号) | 上行流判据 |
| 缺结尾边界 | 3 s | 媒体结束距抓包结束 |
| INVITE/BYE 判定边距 | 1 s | 早于媒体开始 1s / 晚于媒体结束 1s |
